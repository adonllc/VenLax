Admin panel authentication strategy

The design spec requires 2FA for all admin actions. How should admin identity work?

A

Role flag on existing user table

Add role: "user" | "admin" | "superadmin" to the users table. Admin users log in via the same auth endpoints. Admin panel checks JWT role claim; redirects non-admins. 2FA enforced as a second step after login.

Simplest — reuses auth module Role promoted via DB directly Admin on same user surface
B

Separate admin credentials table

A standalone admin_users table with email + bcrypt password, separate JWT signing secret, and its own login endpoint POST /admin/auth/login. Admins can't hold user accounts on the same credentials. TOTP 2FA enforced at login.

Fully isolated Separate JWT secret More schema + routes

Recommendation

B (separate table) — keeps admin identity completely isolated from the product user surface. A compromised user session can never escalate to admin. The extra schema is minimal and the security boundary is worth it given FP adjustment and market resolution powers.
