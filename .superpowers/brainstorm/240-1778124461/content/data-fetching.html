Data fetching strategy — web + mobile

Both apps need to talk to the Fastify API. How should they manage server state?

A

TanStack Query (React Query v5)

One library on both web and mobile. useQuery / useMutation hooks. Automatic background refetch, cache invalidation, optimistic updates for forecast entry. Same pattern works in Next.js client components and React Native.

Shared pattern Cache + optimistic UI Works on web + RN New dep to add
B

Next.js Server Components + Server Actions (web only)

Web uses RSC for market pages (SSR, no client JS needed). Interactive mutations go through Server Actions. Mobile still uses plain fetch hooks. Two different patterns — web is server-first, mobile is client-side.

Best web performance No extra dep on web Two different patterns Server Actions ≠ RN
C

Hybrid — RSC for public pages, React Query for interactive UI

Market browse/detail pages use RSC for SSR + SEO. Once a user interacts (forecast entry, reviews, wallet), React Query takes over for live updates and cache. Mobile uses React Query throughout. Best of both.

SSR where it matters RQ for real-time UI Shared RQ on mobile Two patterns to learn

Recommendation

C (Hybrid) — RSC handles market detail pages for SEO and OG cards (no JS needed for the share preview). React Query handles all authenticated, interactive surfaces (forecast entry, wallet, reviews) and is shared with mobile.
